# Полное руководство по использованию системы автоматизации предписаний (prescriptions_system)

Данная система предназначена для автоматизации жизненного цикла предписаний строительного контроля: от загрузки скан-копий и автоматического извлечения данных с помощью LLM до контроля исполнения и уведомления ответственных лиц через Telegram.

---

## 1. Системные требования

Перед установкой убедитесь, что в системе установлены следующие компоненты:

### Обязательное ПО:
- **Python 3.12**: Строго эта версия.
  - *Windows*: `winget install -e --id Python.Python.3.12`
- **Ollama**: Локальный движок для запуска LLM и эмбеддингов.
  - Скачать с [ollama.com](https://ollama.com).
  - **Запуск**: В Windows Ollama устанавливается как системный сервис и автоматически запускается при старте ОС. Вы увидите иконку ламы в системном трее (возле часов).
  - **Проверка работы**: Откройте браузер и перейдите по адресу `http://localhost:11434`. Если вы видите сообщение *"Ollama is running"*, значит сервис работает корректно.
- **Git**: Инструмент для управления версиями кода.
  - **Установка**: Скачайте установщик с [git-scm.com](https://git-scm.com). При установке можно оставлять все настройки по умолчанию.
  - **Проверка**: Введите в терминале `git --version`. Если версия отобразилась, Git установлен.


### Рекомендуемое ПО:
- **Visual Studio Code** или любая IDE с поддержкой Python.
- **Postman** или любой HTTP-клиент (для тестирования API).

## 2. Пошаговая установка и развертывание

### Шаг 1: Инициализация проекта
Откройте терминал (PowerShell в Windows) в корне папки `prescriptions_system` и запустите скрипт автоматической настройки:

```powershell
.\scripts\setup_local.ps1
```
**Что делает этот скрипт:**
- Создает виртуальное окружение `.venv`.
- Обновляет `pip` и устанавливает базовые зависимости из `requirements.txt`.
- Создает необходимые системные папки (`data/`, `backups/` и др.).
- Создает файл `.env` из шаблона `.env.example`.
- Запускает базовые тесты конфигурации.

### Шаг 2: Активация окружения
Все последующие команды должны выполняться в активированном виртуальном окружении:

```powershell
.\.venv\Scripts\Activate.ps1
```

### Шаг 3: Загрузка ML-моделей
Система использует локальные модели для извлечения данных и поиска по документам. Модели не скачиваются автоматически при установке Ollama, их нужно загрузить отдельно.

Запустите скрипт автоматической загрузки (при этом Ollama должна быть запущена в фоновом режиме):

```powershell
.\scripts\pull_models.ps1
```

**Как это работает:**
Скрипт отправляет команды в API Ollama, которая скачивает веса моделей из официального реестра.
- `qwen2.5:7b-instruct` — основная LLM для интеллектуального разбора текстов предписаний.
- `bge-m3` — специализированная модель эмбеддингов, которая превращает текст в математические векторы для RAG.

**Ручное управление моделями:**
- Чтобы проверить список всех установленных моделей: `ollama list`
- Чтобы вручную скачать модель: `ollama pull qwen2.5:7b-instruct`
- Чтобы запустить чат с моделью в консоли: `ollama run qwen2.5:7b-instruct`


### Шаг 4: Настройка секретов и конфигурации
Откройте файл `.env` в текстовом редакторе и заполните следующие поля:

- `WEB_SECRET_KEY`: Сгенерируйте случайную строку. 
  *(Команда для генерации: `python -c "import secrets; print(secrets.token_hex(32))"`)*
- `TELEGRAM_BOT_TOKEN`: Токен вашего бота, полученный от @BotFather.
- `FIRST_ADMIN_LOGIN`, `FIRST_ADMIN_PASSWORD`: Данные для первого входа администратора.

Основные системные пути и настройки моделей находятся в `config.yaml`.

### Шаг 5: Создание первого администратора
Чтобы войти в систему, необходимо создать учетную запись администратора в базе данных:

```powershell
python scripts\create_first_admin.py
```

## 3. Дополнительные модули (по необходимости)

### Работа со сканами (OCR)
Если вы планируете обрабатывать не текстовые PDF, а изображения или сканы (где текст нельзя выделить курсором), установите PaddleOCR:

```powershell
pip install -r requirements-ocr.txt
```
*Примечание: Это установит библиотеку PaddlePaddle (~600 МБ).*

### База знаний (RAG - Retrieval-Augmented Generation)
Система использует технологию RAG, чтобы не просто «гадать», а давать рекомендации на основе реальных нормативных документов (ГОСТ, СНиП).

**Принцип работы:**
`PDF-файл` $\rightarrow$ `Извлечение текста` $\rightarrow$ `Разбиение на фрагменты (Чанки)` $\rightarrow$ `Преобразование в векторы (модель bge-m3)` $\rightarrow$ `Сохранение в векторную БД ChromaDB`.

**Пошаговая настройка:**
1. **Подготовка данных**: Создайте папку `docs/priors/` и поместите туда все PDF-файлы с нормами, которые должны быть доступны системе.
2. **Индексация**: Запустите скрипт загрузки. Он прочитает все файлы, создаст эмбеддинги и сохранит их в папку `data/chroma`:
```powershell
python scripts\load_norms.py docs\priors\ --pattern "*.pdf"
```
3. **Использование**: Теперь при анализе предписания система будет искать в ChromaDB наиболее подходящие по смыслу фрагменты из ваших документов и добавлять их в отчет как «Основание/Рекомендация».

**Обновление базы**: Чтобы добавить новые документы, просто положите их в папку и повторите команду загрузки.


### Генерация отчетов
Для поддержки экспорта в PDF (через WeasyPrint) и XLSX:
```powershell
pip install -r requirements-reports.txt
```

## 4. Запуск системы

Система состоит из нескольких независимых компонентов. Для полноценной работы запустите их в разных окнах терминала (в каждом активируйте `.venv`):

| Компонент | Команда запуска | Описание |
| :--- | :--- | :--- |
| **Web-интерфейс** | `python prescriptions_system\scripts\run_web.py` | Основная панель управления (http://127.0.0.1:8000) |
| **Уведомления** | `python prescriptions_system\scripts\run_notification_worker.py --interval 5` | Доставка сообщений в Telegram и другие каналы |
| **Telegram-бот** | `python prescriptions_system\scripts\run_bot.py` | Интерфейс для подрядчиков и инспекторов в TG |
| **OCR-пайплайн** | `python prescriptions_system\scripts\run_ocr_pipeline.py` | Мониторинг папки inbox и распознавание новых файлов |

## 5. Интеллектуальное извлечение данных из PDF-сканов

Одной из ключевых функций системы является автоматический перевод скан-копии предписания Заказчика в структурированную запись в базе данных. 

### Как работает пайплайн «Скан $\rightarrow$ БД»:

1. **OCR-распознавание (Optical Character Recognition)**:
   - Когда вы кладете файл в `data/prescriptions/inbox/customer/`, скрипт `run_ocr_pipeline.py` обнаруживает его.
   - Если PDF является текстовым, текст извлекается напрямую через `PyMuPDF`.
   - Если PDF является сканом (картинкой), используется `PaddleOCR`, который анализирует изображение и переводит его в текстовый вид, стараясь сохранить структуру документа.

2. **LLM-экстракция (Интеллектуальный разбор)**:
   - «Сырой» текст из OCR отправляется в модель `qwen2.5:7b-instruct` с детальным системным промптом.
   - Модель анализирует текст и выделяет конкретные поля, необходимые для записи в БД:
     - **Номер предписания** (поиск паттернов типа "№ 123-П").
     - **Дата выдачи** (нормализация даты в формат YYYY-MM-DD).
     - **Срок исполнения** (извлечение даты или количества дней).
     - **Пункты нарушений** (выделение сути претензий Заказчика).
     - **Требуемые мероприятия** (что именно подрядчик должен сделать для устранения).
   - Модель также определяет, является ли документ именно «Предписанием Заказчика» по ключевым словам в шапке и подписям.

3. **Валидация и запись в БД**:
   - Извлеченные данные формируются в JSON-объект.
   - Запись создается в БД со статусом `pending_review` (ожидает проверки).
   - **Важно**: Данные не попадают в основной реестр автоматически — они сначала отображаются в веб-интерфейсе для инспектора.

4. **Подтверждение инспектором**:
   - Инспектор заходит в веб-интерфейс, проверяет извлеченные поля, сверяя их с оригиналом скана.
   - После нажатия кнопки «Подтвердить», запись получает статус `fixed_pending_review` и становится официальным предписанием в системе.

## 6. Что проверить после установки (Чек-лист)


### Техническая проверка
Запустите тесты, чтобы убедиться, что все зависимости и база данных работают корректно:
```powershell
python -m pytest
```

### Функциональный сценарий (MVP)
Проверьте прохождение документа по всей цепочке:

1. **Загрузка**: Положите любой PDF-документ (предписание) в папку `data/prescriptions/inbox/customer/`.
2. **Распознавание**: Запустите `run_ocr_pipeline.py`. Файл должен переместиться в `processed/` или `storage/`.
3. **Проверка в Web**: Зайдите в веб-интерфейс $\rightarrow$ Реестр предписаний. Найдите загруженный документ.
4. **Анализ LLM**: Проверьте, правильно ли система извлекла номер, дату и пункты предписания.
5. **Жизненный цикл**: 
   - Смените статус предписания на "В работе" или "Исполнено".
   - Добавьте комментарий или вложение.
6. **Уведомление**: Проверьте, пришло ли соответствующее уведомление в Telegram-бот.
