# Надёжность, резервное копирование и восстановление (Шаг 12)

## Принципы

- SQLite в WAL-режиме; `PRAGMA foreign_keys=ON` на каждом подключении
  (`src/db/engine.py`).
- Оригиналы документов (inbox → storage → processed, uploads, подписанные сканы,
  печатные версии) не удаляются никогда.
- Идемпотентность всех пайплайнов: повторный запуск OCR — по SHA-256 файла
  (`processed_files`), повторное событие уведомления — по уникальному ключу
  (`notifications`), перезагрузка норм — заменой чанков по коду документа.
- Каждое уведомление сначала фиксируется в БД (outbox, pending) — и только
  потом отправляется воркером.

## Резервное копирование

Состав снапшота:

1. Консистентный снимок БД через `sqlite3` backup API
   (безопасен при WAL; простой `copy` файла БД запрещён);
2. Копия каталога `data/` (кроме служебного `ocr_workspace` и файлов БД):
   `prescriptions/inbox`, `prescriptions/processed`, `prescriptions/storage`,
   `uploads`, `chroma`;
3. `manifest.json` — SHA-256 каждого файла и снимка БД.

Запуск (ежедневно по планировщику):

```powershell
# Windows
.\scripts\backup.ps1 -Keep 14
# Linux
./scripts/backup.sh 14
```

Снапшоты складываются в `backups/backup_<UTC-время>_<хеш>/`, автоматическая
ротация хранит последние N (по умолчанию 30). Хранение вне рабочей машины
(внешний диск/сетевая шара) — ответственность эксплуатации: синхронизируйте
каталог `backups/`.

## Проверка целостности снапшота

```powershell
python scripts\restore_backup.py backups\backup_... 
```

Скрипт до любых действий выполняет `PRAGMA integrity_check` на копии БД из
снапшота и сверку SHA-256 всех файлов из manifest.json; при расхождении —
отказ с nonzero-кодом.

## Порядок восстановления

1. Остановить веб-приложение, воркер уведомлений, бота и пайплайн OCR.
2. Выбрать последний проверенный снапшот в `backups/`.
3. Восстановить:

   ```powershell
   .\scripts\restore_backup.ps1 backups\backup_2026-10-03_120000_ab12cd -Force
   ```

   Существующая БД предварительно переименовывается в `*.backup-<ts>.db`
   (не удаляется).
4. Выполнить чек-лист (ниже).
5. Запустить сервисы; при недоступности RAG-коллекции — перезагрузить нормы
   `scripts/load_norms.py`.

### Чек-лист проверки восстановления

1. Скопировать последний снапшот БД и файлов на чистую среду (или каталог).
2. Открыть БД: `PRAGMA integrity_check` → `ok`
   (`python -c "import sqlite3;print(sqlite3.connect('data/prescriptions.db').execute('PRAGMA integrity_check').fetchone())"`).
3. Сверить SHA-256 восстановленных оригиналов с `processed_files.sha256`
   (`scripts/restore_backup.py` делает это по manifest автоматически).
4. Проверить, что в реестре (`/prescriptions`) отображается последний
   зарегистрированный номер предписания.
5. Запустить тестовый прогон OCR-пайплайна на копии inbox:
   `python scripts\run_ocr_pipeline.py --inbox <копия>` — дубли не создаются
   (все файлы уже в `processed_files`).
6. Проверить недоставленные уведомления: воркер продолжит попытки по
   `next_attempt_at` (записи `failed` остаются в БД).

## Переключатели системы (таблица system_config)

| Ключ | Значение по умолчанию | Назначение |
|---|---|---|
| `send_notifications_before_confirmation` | отсутствует (false) | разрешает слать уведомления Подрядчику до подтверждения данных инспектором (§0.4.3; по умолчанию — запрет) |

Значения читаются сервисом уведомлений из таблицы `system_config`; отсутствие
записи = безопасный default.

## Структурированное логирование

Все пайплайны (OCR, воркер уведомлений, бот, веб, CLI-скрипты) вызывают
`src.observability.configure_logging()` и пишут JSON-строки:
`ts`, `level`, `logger`, `message` + контекст (например, `prescription_id`,
`notification_id`, `engine`, `sha256`). Настройки — `logging.level` и
`logging.json_logs` в `config.yaml`.

Ошибки доставки уведомлений дополнительно хранятся в БД
(`notifications.last_error`, `notification_attempts.error`) — журналы не
заменяют данные.

## Многопользовательский режим

SQLite (WAL) рассчитан на один хост. При росте числа пользователей — переход
на PostgreSQL: SQLAlchemy-модели и миграции Alembic совместимы; меняется
только `db.url` (строка postgresql+psycopg).
