# Контракт интеграции MAX (Шаг 14)

**Статус: API ботов MAX не подтверждён. Канал помечен недоступным; доставка идёт
через Telegram. Этот документ фиксирует, что требуется получить/реализовать,
чтобы подключить MAX без изменения бизнес-логики.**

## 1. Вопросы, на которые нужна официальная спецификация (§0.4)

1. Есть ли официальный HTTP API ботов MAX (аналог Bot API Telegram)? Базовый URL?
2. Модель авторизации: статический токен бота / OAuth / ключ приложения.
3. Способ приёма сообщений: long polling `getUpdates` или webhook (подпись, TLS)?
4. Формат идентификатора получателя (`user_id`, `chat_id`) и его стабильность.
5. Поддержка файлов: отправка PDF/изображений, лимиты размера, способ загрузки
   вложений (file_id или multipart).
6. Inline-кнопки/команды: есть ли callback-события и их формат.
7. Идентификатор отправленного сообщения для `external_message_id` и статусы доставки.
8. Rate limit и политика повторных отправок.

## 2. Контрапт, который должна закрыть интеграция

Существующий контракт адаптера (Шаг 8) — `src/notifications/adapters/base.py`:

```python
class NotificationAdapter(Protocol):
    def is_available(self) -> bool: ...
    def send(self, message_text: str, recipient_address: str) -> str: ...
    def send_file(self, recipient_address: str, file_path: str,
                  caption: str | None = None) -> str: ...
```

Реализация `MaxAdapter` (`adapters/max.py`) должна:
- читать `MAX_API_BASE_URL` / `MAX_API_TOKEN` из `.env` (уже заложены);
- `is_available()` → True только при наличии рабочего API;
- `send()/send_file()` возвращать идентификатор сообщения (в `external_message_id`),
  при ошибке — бросать `AdapterError` (воркер сам применит бэккофф);
- не содержать никакой бизнес-логики.

## 3. Точки подключения (логика менять не нужно)

- **Роутер** (`notifications/router.py`): MAX-канал начнёт выбираться, когда
  `MaxAdapter.is_available()` вернёт True и у получателя появится активный
  `recipient_channels(channel='max', address=...)` — инфраструктура уже есть.
- **Бот** (`bots/max_bot.py`): сейчас заглушка; при подключении обработчик обязан
  вести пользователя через привязку чата в `recipient_channels` и вызывать те же
  сервисы, что и Telegram (`src/bots/handlers.py` переиспользуется напрямую:
  он транспорт-агностичен).
- **Голосовой ввод** (`src/llm/stt/`): интерфейс `transcribe(wav_path) -> text`;
  аудио → STT → текст → LLM-извлечение (Шаг 6) → проверка инспектором. Результат
  всегда `requires_review=True`.

## 4. Требования к данным

- Тип канала уже в системе: `NotificationChannel.MAX`, ограничений схемы нет.
- История доставок: `notifications`/`notification_attempts` — совместимы с MAX
  без миграций.

## 5. Порядок подключения (после получения ответов)

1. Реализовать `MaxAdapter` (и при необходимости webhook-эндпоинт в web-слое).
2. Включить канал в роутере (убрать признак недоступности).
3. Добавить обработчик `bots/max_bot.py` поверх `handlers.process_update`.
4. Тесты с фейковым транспортом (без сети), затем Canary-режим на одном чате.
