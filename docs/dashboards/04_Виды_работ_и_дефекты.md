# 04. Проблемные виды работ и повторяющиеся дефекты

Назначение: выявлять технологические направления, где чаще всего возникают
замечания СК, анализировать повторяемые дефекты, оценивать скорость устранения
и формировать профилактические меры. Аудитория: главная инженерная служба,
 служба строительного контроля, руководители проектов
(`manager`, `inspector`, `admin`).

Экран отвечает на вопросы:

1. По каким видам работ больше всего замечаний?
2. По каким видам работ больше всего замечаний категории А?
3. Какие виды работ имеют худшую дисциплину устранения?
4. Где замечания повторяются после устранения?
5. На каких объектах и у каких подрядчиков конкретный вид работ наиболее проблемный?
6. Какие причины замечаний образуют основную массу дефектов?
7. Какие профилактические действия нужны?

Поле «вид работ» — `work_types` (миграции M3, 00 §8): **гибридный
справочник** — значения добавляются вручную через `/admin/directories` и при
вводе предписания (по образцу действующего `prescription_kinds`). Дизайн
обязан корректно работать с неограниченным числом новых категорий: списки —
скроллируемые внутри блока, цвета — генерируемая палитра из 12 тонов
тёмно-синей/серой гаммы, «прочие» агрегируются при > 12 значений в донат-графиках.

Все числа — **пример**. Определения — [00 §4](00_Обзор_и_общие_правила.md).

## 2. KPI (считаются по выбранному виду работ)

| # | Показатель | Формула |
|---|---|---|
| W1 | Всего замечаний по виду | COUNT(`work_type_id = X`) за период |
| W2 | Открытые | W1 ∧ OPEN_STATUSES |
| W3 | Просроченные | W2 ∧ `deadline < today` |
| W4 | Категория А | W1 ∧ cat=A (из них открытые — сноской) |
| W5 | Доля закрытия в срок, % | 00 §4 по устранённым W1 |
| W6 | Средний срок устранения, дн | 00 §4 по устранённым W1 |
| W7 | Повторные замечания | W1 ∧ `recurrence_of IS NOT NULL` (M5) |
| W8 | Уникальные типовые причины | COUNT(DISTINCT подтверждённый кластер M6 в пределах W1) |
| W9 | Динамика к прошлому периоду | (W1_тек − W1_пред)/W1_пред × 100, ▲/▼ |

## 3. Метод группировки повторяющихся причин (кластеры дефектов, M6)

Конвейер (фоновая задача; инфраструктура эмбеддингов уже есть —
`rag/embeddings.py` + ChromaDB, логование `llm_rag_logs`):

1. **Источники текста:** поле `justification` (обоснование) + `description`
   (текст замечания). Исходные формулировки **никогда не изменяются** —
   кластер только ссылается на предписания.
2. **Нормализация (для вектора):** приведение регистра, удаление пунктуации и
   номерных токенов (нумерация документов, дат, координат), лемматизация,
   подстановка-плейсхолдеры для идентификаторов; вес `justification` выше
   (например 0,6/0,4).
3. **Семантическая кластеризация:** эмбеддинги → косинусная близость;
   кандидаты в кластеры при пороге similarity ≥ 0,82 (настраиваемый); название
   кластера — LLM-резюме частотных формулировок (черновик до подтверждения).
4. **Подтверждение специалистом СК:** кластер «активен» только с
   `confirmed_by_user_id` (как `NormRefStatus`); неподтверждённые видны в
   админ-режиме с меткой «предложено».
5. **Ручное управление:** операции «объединить кластеры», «выделить предписание
   в новый кластер», «исключить из кластера» — через `/admin/directories` и
   карточку предписания; изменения пишутся в историю, centroid пересчитывается.
6. **Вывод блока кластера (Q7/Q8):** название группы, число случаев, объекты,
   подрядчики, преобладающая категория, средний срок устранения, % повторного
   возникновения (доля замечаний кластера, закрытых, а затем снова выявленных
   на том же участке/виде — по M5).

Привязка вида работ к кластеру наследуется от предписаний (M3); новый вид
работ автоматически попадает в те же аналитики без доработки.

## 4. Примеры типовых групп причин (пример названий кластеров)

1. «Отсутствует или не оформлена исполнительная документация»
2. «Отсутствуют акты освидетельствования скрытых работ»
3. «Отсутствуют паспорта/сертификаты материалов»
4. «Отклонение геометрических параметров от проекта»
5. «Нарушение технологии бетонирования»
6. «Дефекты сварных соединений»
7. «Нарушения при антикоррозийной и огнезащитной защите (АКЗ/ОГЗ)»
8. «Отсутствие геодезической исполнительной съёмки»

Перечень иллюстративный: реальный набор формируется данными и справочником;
включать: монолитные, сварочные, геодезические работы, ведение исполнительной
документации, АКЗ/ОГЗ, общестроительные, монтаж металлоконструкций, земляные,
инженерные сети + пользовательские значения.

## 5. Индекс проблемности вида работ (0–100)

`Индекс = 100 × (0,35·D_A + 0,25·D_over + 0,20·T_norm + 0,20·D_rep)`

где по выбранному виду работ за период:

| Слагаемое | Доля (вес) | Расчёт |
|---|---|---|
| D_A | 0,35 | доля замечаний категории А = W4/W1 |
| D_over | 0,25 | доля просроченных = W3/W2 (при W2=0 → 0) |
| T_norm | 0,20 | нормированный средний срок устранения |
| D_rep | 0,20 | доля повторных = W7/W1 |

**Нормирование T_norm:** линейная min-max по распределению всех видов работ
на наблюдаемом горизонте (по умолчанию 12 месяцев, не менее 10 записей на вид;
для «тонких» видов — сглаживание: T_norm = t·k, k = min(1, n/10)).
0 соответствует сроку ≤ 3 дней, 1 — сроку ≥ P95 по всем видам; значения вне
диапазона обрезаются (clip 0…1). Пересчёт — еженедельно, состав среза
запоминается в подписи графика.

**Интерпретация:** 0–24 — стабильная ситуация (серый/зелёный);
25–49 — требуется контроль (жёлтый); 50–74 — проблемная зона (оранжевый);
75–100 — критическая зона (красный). Веса и пороги — в `system_config` (M8).

Индекс показывается в Q1 как цвет бара и число; в детализации — расклад по
слагаемым (waterfall при клике).

## 7. Автоматический блок рекомендаций по проблемному виду работ

Формируется при индексе ≥ 50 (§5) или нажатии «рекомендации» в Q8;
правила — детерминированные, действия исполняются через 00 §7:

| Триггер | Рекомендация |
|---|---|
| индекс ≥ 75 | провести целевой технический аудит направления |
| кластер на ≥ 3 объектах (Q8) | проверить аналогичные зоны и конструкции |
| доля повторных > 15% (W7) | провести инструктаж мастеров подрядчика |
| просрочка > 30% (D_over) | запросить план корректирующих мероприятий у подрядчика |
| вид работ требует технологии | проверить наличие и актуальность технологической карты |
| кластеры §4.2–4.3/4.8 (документы, материалы, съёмка) | усилить входной контроль материалов / документооборота |
| индекс 25–49 | провести выборочную повторную проверку |

## 8. Пример наполнения (пример!)

- Q1 топ: монолитные работы — 34 замечания, индекс 68 (оранж.); сварочные — 21,
  индекс 74; исполнительная документация — 28, индекс 41.
- W-строка для «монолитные»: W1 34 · W2 12 · W3 5 · W4 3 · W5 71% · W6 9,8 дн ·
  W7 4 · W8 6 · W9 +13% ▲.
- Q7 Парето: «нарушение технологии бетонирования» — 9 случаев (26%),
  «отклонение геометрии» — 7 (46% накоп.).

## 9. Критерии приемки (специфичные для 04)

1. Добавление нового вида работ в справочник (ручной ввод) сразу отражается
   в Q1–Q6 и фильтрах без изменений кода; при 25+ видах интерфейс не ломается
   (скролл/агрегация «прочие»).
2. Кластер не влияет на аналитику, пока не подтверждён; ручное объединение/
   разъединение корректно пересчитывает W8, Q7, Q8 (тест слияния).
3. Индекс проблемности воспроизводится формулой §5 на контрольном наборе;
   нормирование T_norm стабильно при добавлении данных (пересчёт еженедельно,
   окно закреплено в подписи).
4. Q9 по клику из любого блока даёт набор записей, сходящийся с числом блока.
5. Рекомендации §7 появляются по триггерам и содержат исполняемые кнопки.
